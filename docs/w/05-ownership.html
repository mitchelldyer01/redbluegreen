Ownership

Every kernel resource is a type with a Drop, so the teardown order comes from the tree and not from the caller.

Drop is the method Rust runs when a value goes out of scope. In unit 3 every kernel resource became a type with a Drop, so the types carry the teardown order and the caller no longer has to remember it. The owner named ownership the theme of the unit.

Kfd holds the two fds and the gpu_id, and its Drop closes both fds. Buffer holds a va, a size, a handle, flags and a view_mapped bit; its Drop does munmap, UNMAP and FREE. A Drop cannot fail, so an error inside it prints to stderr and the work goes on. as_slice_mut borrows through the Buffer, so a slice cannot outlive the memory behind it, and remap drops the host view and retakes it. Queue owns the ring, write_ptr, read_ptr, cwsr and eop Buffers with the doorbell mapping; its Drop sends DESTROY_QUEUE, munmaps the doorbell, and then lets the Buffers drop in declaration order. Event owns an event id and its page. Kernel and Signal each hold one Buffer.

Every syscall returns Result<T, Error>. The Error carries the call name and the errno, and it prints as "call: message". main prints it and exits 1. There is no die().

This mattered because the flat functions of unit 2 leaked a handle on any early exit until the process ended. A leak of 1 MiB is nothing. A training run keeps a corpus of gigabytes resident, and a GPU hang on this APU takes the desktop with it. Ownership is the cheapest guard, and it is the reason Rust was chosen over C. Two runs prove that Drop runs on the error path: the too-small CWSR run, which got EINVAL from the kernel, exited 1 and left GTT unchanged, and the forced verify failure in unit 2.

Nesting gives the order for free. A Queue drops its own fields first and then its Buffers, so DESTROY_QUEUE always runs before the ring memory is freed. The next page dispatches a kernel into this queue.
