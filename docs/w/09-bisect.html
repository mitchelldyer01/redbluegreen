The bisect

Ten one-question kernels that turned a vadd hang into a rule about VGPR blocks.

vadd hung on its first run. The harness printed rptr 0, signal 1 and c[0] 0: the packet never retired and the kernel never reached its store. The log showed no fault. Every experiment cost one GPU reset, so a guess was expensive. Each kernel below answers exactly one question, and the order gets the most information per reset. All of them run with one wave, one element, and the harness unchanged.

store42 at workgroup 256 ran eight waves of known-good code and passed, so eight waves are safe. vadd as one wave hung, and it hung again on fine-grained data, so the data type is clear. vload proved one vector load. sload proved the three scalar loads, including the 128-bit one. vbranch proved the exec-mask sequence and the branch. Each of those passed.

vadd2 is vadd with the second load in v0 instead of v4. Two dwords are the only difference between the two kernels. Their descriptors are identical, because 4 and 5 registers encode to the same block: the assembler counts VGPRs in blocks of 8 for wave32. vadd2 passed. vadd16 then took vadd's exact bytes and moved the register field one block higher, and it runs. That pair is the proof.

Rule 3 follows: ask the assembler for 8 more VGPRs than the code uses. Block 0 does not give a wave five usable registers, whatever the encoding says. The limit of the result is honest. v4probe passed alone, so one load into v4 does not hang a wave; the failure needs a second load in flight. The mechanism stays unknown and the rule is known.

Method notes. sdump could not hang, so it ran first, and it showed that every register vadd depends on was correct: a, b, n, the workgroup id and the lane id. On timeout the harness prints rptr, signal and c[0], so even a hang reports whether the packet retired and whether the kernel stored. The bisect kernels stay committed under src/kernels/ as the record. This page cost about eight resets.
