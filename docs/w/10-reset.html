The reset chain

One new GPU mapping, made while another process was busy, walked a chain of seven steps to a GPU reset.

The symptom was narrow. A queue created while a local model server was generating never ran, and the GPU reset two to three seconds in. Our own code looked correct, so the first job was to find the faulty half.

Eight experiments, one reset at most each, in order. Two of our processes at once, 64M and 1000 reps: both finish. Twelve at once: all finish, with the bandwidth shared. The server up but idle: a 64M add at full speed. The add started first and the server generating mid run, 20000 reps: all results verify at half speed. That run proves our queues survive pauses; the twelve-process run proves it twice. Then the failures. A queue created during generation hangs and resets the GPU. The same follows with the context save header filled, with RUNTIME_ENABLE, and with 1-element buffers, where the queue ran its first packet before the reset came. Every kernel log named the server queue as the one the driver failed to evict, and the server as the process it failed to suspend.

The driver source gives the chain. Page tables are allocated in VRAM on this chip, and only app APUs use system memory. A new mapping needs page-table pages, so TTM evicts another process's VRAM buffer. A kfd buffer carries an eviction fence, so evicting it means pausing that process's queues with REMOVE_QUEUE through MES. MES cannot pause a mid-kernel queue in time, the driver declares MES unrecoverable, and both processes die.

Three candidate fixes were wrong for one reason. The context save header, the executable flag on the save area, and RUNTIME_ENABLE all concern pausing our queue, which was never the queue being paused. Rule 4 follows: allocate every GPU buffer at start, never inside a loop, never while another process is busy.

The reset history agrees. One reset on the first day, 31 on the second, none in the 30 days before, and every one was ours. The scheduler gives 10 ms per process and 1 ms per gang; the twelve-process pass shows our waves survive that switching.
