redbluegreen wiki

A GPU training toolchain for one machine, written down so the reasoning survives.

"I want to train and work with models more closely, but my hardware has some serious limitations. Support is full of gaps and it is not obvious how the off-the-shelf software is meant to work; I am constantly pinning versions and community forks."

the owner

redbluegreen is a GPU training toolchain for one machine, an AMD Strix Halo APU. The toolchain is built from the kernel interface up, with no GPU userspace under it. The consumer is david: two small diffusion models, a graph coupling model over discrete edges and a code span model. Both must train in one night on this box. This site exists so the owner can re-derive the reasoning behind each decision a year on. The voice is a dry lab notebook.

The layers are kfd and queue; memory; kernels; autograd; optimizer; loop; and data resident in GPU memory. Each layer uses only the layer below it. Unit 1 talks to the driver with GET_VERSION and ACQUIRE_VM. Unit 2 owns memory with ALLOC, MAP and a host view. Unit 3 owns the queue: Drop types, an AQL queue and an event. Unit 4 dispatches one kernel that writes 42. Unit 5 adds two vectors at 225 GB/s. Unit 5b survives a pause; the root cause was page tables in a full carve-out. Nothing above layer 3 exists yet. The toolchain has zero external dependencies at run time. The build needs llvm-mc and llvm-objcopy to assemble kernels, and rustc. There are no crates.

The price so far is 31 GPU resets on 2026-09-22. Each reset is now a rule that is written down, and the owner calls the list "thirty one ways not to make a lightbulb". A 27B local model (Qwen) in a coding agent wrote the implementation from one-page prompts; the owner ran the GPU steps. The pages below take one mechanism each.
